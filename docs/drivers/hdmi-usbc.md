- 2026-11-04 18:20: **HDMI PICTURE STRAIGHT + UNPLUG HANG CAUGHT.** (1) The slanted/blue HDMI checkerboard was OUR TOOL: drmfill asked for at most 8 modes; the kernel copies the mode list only if the buffer holds all of them, so for the TV (many modes) it copied none and drmfill drove DP with the previous connector's stack leftovers = the phone panel's 1350x1800 timing. Fixed (drmfill.c sizes the buffer from the count, prints the chosen mode, `DRMFILL_MODE=WxH[@Hz]` picks one): kernel #67 + fixed drmfill -> TV straight checkerboard at its preferred 3840x2160@30 (webcam). The no-wide-bus patch stays (matches DPU 5.0) but did not cause the shear. (2) The hang ~60 s after moving the cable back to the PC (twice; garbled screens, watchdog never fired) happened exactly when drmfill exited = when the DP pipe was turned off after the unplug. Reproduced with /proc/kmsg streamed to the PC and drmfill killed by hand: vblank timeout -> msm_disp_snapshot -> msm_dp_snapshot -> "synchronous external abort" in msm_disp_snapshot_add_block (artifacts note: kmsg-dpfreeze, a local folder). After an unplug the DP driver runs ctrl_off_link + host_phy_exit but power_on stays true, and the snapshot only checks power_on -> it reads the unclocked DP block. Fix: patches/msm-dp-snapshot-unclocked.py (also require core_initialized + phy_initialized), kernel #68; init sets panic_on_oops so such an oops resets the phone (panic=10 -> watcher) instead of wedging it. Also seen: the switch back to device mode itself works (configured in ~4 s); `g_mass_storage` tries to bind the UDC on the role switch (-22, harmless); the top panel sometimes boots into noise (`dsi_err_worker: status=4`, cold DSI) on test boots without sway. 60 Hz HDMI: 1080p/1440p@60 fit the current 2-lane DP + USB3 mode; 4K@60 needs 4-lane DP-only (dock USB drops to USB 2).
